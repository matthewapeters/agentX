# Transport Backlog — External-Surface Enablement (M1)

Last updated: 2026-06-29
Status: Execution-ready backlog
Owner: Delivery Lead
Scope: The HTTP/SSE transport, surface registry, ephemeral attach tokens, port
allocation, and `agentx surface launch` CLI that let **external surface processes**
attach to a running orchestrator over the network boundary.

## Context

`docs/build-plan/01_comprehensive_build_plan.md` defines milestone **M1 (Runtime
Skeleton And Surface Registration Foundation)** at the capability level. The
chat-surface slice (`03_chat_surface_backlog.md`) delivered the **runtime skeleton**
half of M1 (orchestrator lifecycle, config, session, event bus, processing-state,
entrypoint) but **deliberately deferred the surface-registration / transport half**:
the default chat surface is an *in-process* subscriber to `internal/state`, so it
never needed the network boundary (see `03_chat_surface_backlog.md` "Out of scope":
*HTTP/SSE transport, surface registration, attach tokens, port allocation,
launch-command generation, multi-instance → M1 (external-surface enablement)*).

This document is the missing task tier for that deferred half. It implements the
frozen contracts in:

- `docs/implementation/02_surface_orchestration_http.md` (Surface Model, Port
  Allocation, HTTP API Baseline v1, Normative CLI Specification, Processing State
  Contract, Surface Registration Contract, Attach security contract, Non-Goals)
- `docs/architecture/runtime_contracts/surface-registration.schema.json` (frozen v1
  registration payload incl. `attach_token_fingerprint`)
- `docs/architecture/runtime_contracts/processing-state.schema.json` /
  `event-envelope.schema.json` (the payloads the transport streams)
- `docs/implementation/08_go_module_layout.md` (Import Direction Matrix:
  `internal/transport/http`, `internal/surfaces/registry`, `internal/cli`)

## Goal (definition of done for the slice)

A running `agentx` (orchestrator + in-process chat) **also serves an HTTP/SSE
endpoint** on an allocated local port and prints copy-pasteable `agentx surface
launch` command strings carrying the endpoint and an ephemeral attach token. A second
process can run that command, register against the live session over HTTP (token
validated), appear in `GET /surfaces` with `lifecycle_state: ready`, receive the same
event + processing-state streams the chat surface sees over SSE, and submit prompts /
approvals back over HTTP — producing the identical orchestrated behavior as the
in-process path. `make all` stays green throughout.

## Locked design decisions

1. **The chat surface stays in-process.** Per the frozen design
   (`02` Surface Model; `03` slice architecture), the transport exists to serve
   *external* surfaces. The default chat surface continues to attach via the existing
   in-process `chat.Bridge`; we do **not** route it through loopback HTTP in v1. The
   HTTP server and the in-process bridge are two adapters over the **same**
   orchestrator API (`Bus()`, `Processing()`, `Submit`, `Resolve`, `Session()`,
   `Accepting()`), so neither owns orchestration logic.
2. **No real peer surface ships in this milestone.** M1 enablement delivers the
   transport, registry, token, port allocation, and CLI — validated end-to-end with a
   **headless test client** (and a thin `--probe`/diagnostic mode for manual smoke).
   The first *rendering* system surface (files / config) is M2 and consumes this
   transport (`04`-style backlog, future).
3. **SSE for orchestrator→surface, HTTP request/response for surface→orchestrator**
   (`02` Transport directionality). No protocol upgrade in v1.
4. **Local-safe transport only** (`02` validation rule 3 + Non-Goals): bind loopback;
   no public/remote access, no multi-node, no cross-machine sessions in v1.
5. **Ephemeral attach token per session**, generated by the orchestrator at start,
   validated at registration; the **raw token is never persisted** — only a
   non-secret fingerprint (`attach_token_fingerprint`) is stored/published, per the
   frozen schema.
6. **Required-surface transport failure blocks startup** (`02` Port Allocation): if
   the HTTP server cannot bind, `agentx` fails clean rather than booting a UI with no
   transport. (Whether the HTTP server is *required* vs. *best-effort* in v1 is
   TRN-6's resolved decision — default: required, with a `transport.enabled=false`
   escape hatch.)

## Architecture of the slice

```
agentx (one process)
├── internal/runtime        orchestrator  ── attach-token mint + registry owner
│      Bus() Processing() Submit() Resolve() Session() Accepting() Shutdown()
├── internal/surfaces
│      registry.go          SurfaceRegistration records + lifecycle + token validate
├── internal/transport/http
│      server.go            loopback HTTP + SSE server (adapter over orchestrator)
│      read/stream/write handlers (GET /events SSE, POST /prompt, …)
│      portalloc.go         conflict-aware port allocation from configured range
├── internal/cli
│      surface_launch.go    `agentx surface launch` (+ compat alias) parse/validate
└── internal/app            wires the HTTP server alongside the in-process chat
```

```
external process:  agentx surface launch <kind> --session <s> --connect <ep> --token <t>
        │ HTTP POST /surface/register  (token validated → fingerprint stored)
        ▼
   orchestrator registry  ── lifecycle_state: provisioning → ready
        │ SSE GET /events            (event-envelope stream, shared)
        │ SSE GET /processing-state  (processing-state stream, shared)
        ▼
   surface renders; sends back POST /prompt, /tool/approval, /surface/{id}/command
```

Every task carries the cross-cutting obligations: a GIVEN/WHEN/THEN behavior doc
before implementation, a Godog feature + steps under the `@unit|@integration|
@functional|@e2e` tag scheme (+ `@arch:transport` / `@arch:surface-registry`), and
AC→test traceability (`01_comprehensive_build_plan.md` §3).

## Phase E — Transport foundation (M1 external-surface enablement)

### TRN-1 · Surface registry + ephemeral attach tokens · M
- **Target**: `internal/surfaces/registry.go`, `internal/runtime/` (token mint)
- **Source**: `02` (Surface Registration Contract, Attach security contract),
  `surface-registration.schema.json`
- **Behavior**: orchestrator mints one ephemeral attach token per session at start
  and exposes its non-secret fingerprint; a registry stores `SurfaceRegistration`
  records (the 8 frozen fields), validates a presented token against the session
  token, transitions lifecycle `provisioning → ready` on accept and `→ stopped` on
  shutdown, and rejects registration on missing/invalid token. Raw token never
  persisted; only the fingerprint is stored/published.
- **Feature**: `tests/features/surfaces/surface_registry.feature`
  (`@functional @arch:surface-registry`)
- **Done**: valid-token register → `ready` + record matches schema; invalid/missing
  token → rejected; shutdown → `stopped`; duplicate `surface_id` → conflict.

### TRN-2 · HTTP server: read + streaming endpoints · M
- **Target**: `internal/transport/http/server.go`, read/stream handlers
- **Deps**: TRN-1
- **Source**: `02` (HTTP API Baseline — Read endpoints, Streaming endpoints,
  Transport directionality, Processing State Contract)
- **Behavior**: a loopback HTTP server adapting the orchestrator. `GET /health`,
  `GET /processing-state` (snapshot), `GET /surfaces` (registry list),
  `GET /sessions/current` (`Session()`); `GET /events` streams the event bus as SSE
  with a per-connection subscription that does not block other subscribers (reuse the
  per-subscriber queue semantics already in `internal/state`). Payloads conform to the
  frozen envelope/processing-state schemas.
- **Feature**: `tests/features/transport/http_read_stream.feature`
  (`@integration @arch:transport`)
- **Done**: reads return canonical state; an SSE client receives ordered events for a
  prompt cycle; a slow SSE consumer does not stall others.

### TRN-3 · HTTP server: write endpoints · M
- **Target**: `internal/transport/http/` write handlers
- **Deps**: TRN-1, TRN-2
- **Source**: `02` (Write endpoints)
- **Behavior**: `POST /surface/register` (→ TRN-1 registry), `POST /prompt`
  (→ `Submit`, gated by `Accepting()`), `POST /tool/approval` (→ `Resolve`),
  `POST /surface/{id}/shutdown` (→ lifecycle `stopped`), `POST /surface/{id}/command`
  (registered-surface command relay). `POST /model/switch` returns a documented
  `not-implemented` in v1 (live model-switch is deferred per `03`). All writes require
  a registered/authorized caller; unauthorized → rejected with a deterministic reason
  category (validation | auth | transport | conflict).
- **Feature**: `tests/features/transport/http_write.feature`
  (`@functional @arch:transport`)
- **Done**: a prompt POSTed by a registered surface drives a full cycle whose events
  arrive over `/events`; an approval POST resolves the gate; unauthorized writes are
  rejected with the right category.

### TRN-4 · Port allocation + endpoint publication · S
- **Target**: `internal/transport/http/portalloc.go`, `internal/config/`
- **Deps**: TRN-2
- **Source**: `02` (Port Allocation)
- **Behavior**: allocate a loopback port from a configured range
  (`[agentx.transport]` port range, deterministic preference by surface kind,
  conflict-aware fallback), check availability before assignment, tolerate concurrent
  `agentx` instances on the same host, and publish the resolved endpoint to local
  session metadata (under the session dir). Bind failure on the required transport
  blocks startup with a clean error.
- **Feature**: `tests/features/transport/port_allocation.feature`
  (`@integration @arch:transport`)
- **Done**: deterministic-preference port chosen when free; fallback on conflict;
  endpoint written to metadata; bind failure → clean non-zero startup error.

### TRN-5 · CLI: `agentx surface launch` + compatibility alias · M
- **Target**: `internal/cli/surface_launch.go`, `cmd/agentx/` (subcommand dispatch)
- **Deps**: TRN-3
- **Source**: `02` (Normative CLI Specification: command forms, argument contract,
  validation rules 1–5, success/failure outcomes, operator messages, Gherkin
  contracts)
- **Behavior**: parse the canonical
  `agentx surface launch <surface-name> --session <name-or-id> --connect <endpoint>
  --token <attach-token>` and the compat alias `agentx -l <kind> -s <session> -p
  <port>` (alias maps port→endpoint before registration). Enforce validation rules
  (known surface-kind, single-session resolution, local-safe endpoint, token
  validation, alias port mapping). On success print `surface_id`, resolved
  `session_id`/`session_name`, connected endpoint, exit 0; on failure print the
  reason category + remediation hint, exit non-zero.
- **Feature**: `tests/features/surfaces/launch_child_surface.feature`
  (`@e2e @ux:CLI`) — mirrors `02` Gherkin Behavior Contracts
- **Done**: canonical + alias launch register a headless surface to the live session;
  invalid token → auth/non-zero; ambiguous session → validation/non-zero;
  unreachable endpoint → transport/non-zero.

### TRN-6 · Serve-alongside wiring + launch-command emission · M
- **Target**: `internal/app/`, `internal/runtime/`, `internal/surfaces/chat/`
- **Deps**: TRN-1…TRN-5
- **Source**: `02` (Launch behavior — "main session prints launch command strings"),
  `01_runtime_blueprint.md` (lifecycle: transport in startup/shutdown sequence)
- **Behavior**: fold the HTTP server into the orchestrator lifecycle (start after the
  bus/processing publishers are live, before serving prompts; drain + stop in
  graceful shutdown). The chat boot path emits copy-pasteable `agentx surface launch …`
  strings (endpoint + token) for each enabled external surface kind. A
  `transport.enabled=false` escape hatch keeps the pure in-process mode working.
- **Feature**: `tests/features/runtime/transport_lifecycle.feature`
  (`@functional @arch:runtime-bootstrap`)
- **Done**: `agentx` starts the HTTP server in lifecycle order and prints valid launch
  strings; a launched headless surface attaches and round-trips a prompt end-to-end;
  shutdown stops the server and marks surfaces `stopped`; `make all` green.

## Sequencing

```
TRN-1 ─┬─ TRN-2 ─ TRN-3 ─┬─ TRN-5 ─┐
       └─ TRN-4 ──────────┘         ├─ TRN-6 ── INTEGRATION ── slice done
                                    │
            (headless test client) ┘
```

- TRN-1 (registry + token) is the keystone; TRN-2/TRN-4 can proceed in parallel once
  the registry interface is fixed.
- TRN-5 (CLI) needs TRN-3 (the register endpoint) to exercise a real attach.
- TRN-6 converges everything into the live `agentx` lifecycle.
- Critical path: TRN-1 → TRN-2 → TRN-3 → TRN-5 → TRN-6.

## Out of scope (explicitly deferred)

| Deferred | Belongs to |
| --- | --- |
| Any *rendering* peer surface (files, config, context, context-history, context-visualizer) | M2 (separate per-surface backlog) |
| Routing the default chat surface over loopback HTTP (stays in-process) | not planned for v1 |
| Live `POST /model/switch` behavior (returns not-implemented) | later M3a |
| Public/remote access, multi-node, cross-machine sessions | `02` Non-Goals (post-v1) |
| Upgraded streaming protocol beyond SSE | post-v1 evaluation |
| Auth beyond the ephemeral per-session attach token | post-v1 |
